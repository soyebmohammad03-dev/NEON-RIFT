## Why a Bootstrap scene

The project never uses `DontDestroyOnLoad` (Decision D2). Long-lived objects live in a scene that stays loaded for the whole session, and exactly **one content scene** is loaded additively on top of it.

## `BootstrapLoader`: entering from any scene

`Assets/_NeonRift/Scripts/Game/BootstrapLoader.cs` has a `[RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.BeforeSceneLoad)]` method, `EnsureBootstrapLoaded`. If no scene named `Bootstrap` is loaded, it loads `Assets/_NeonRift/Scenes/Bootstrap.unity` additively. If Bootstrap is not in the build list, it logs a warning and the game flow is disabled. So pressing Play in **any** scene still goes through the game flow.

## The scenes (build order from `ProjectSettings/EditorBuildSettings.asset`)

| # | Scene | Path | Contents (from the scene file) | Entry point |
|---|---|---|---|---|
| 0 | **Bootstrap** | `Assets/_NeonRift/Scenes/Bootstrap.unity` | `GameRoot`, `LoadingOverlay` (UI Toolkit, `UI/LoadingOverlay.uxml`), `EventSystem` with `InputSystemUIInputModule` | — (composition root) |
| 1 | **Frontend** | `Scenes/Frontend.unity` | Camera, `UIDocument` with `UI/TitleScreen.uxml`, `TitleScreen` | `TitleScreen` |
| 2 | **CarSelect** | `Scenes/CarSelect.unity` (+ `Scenes/CarSelect/` probe data) | The generated crew garage: 69 GameObjects, 21 lights, 1 reflection probe, `VehicleShowroom`, `ShowroomEngine`, Cinemachine cameras, `CarSelectScreen` | `CarSelectScreen` |
| 3 | **TestTrack** (dev) | `Scenes/Dev/TestTrack.unity` | Physics test surfaces and the 1.55 km validation route | `MissionSceneEntry` (mission `Mission_DevTestTrack`) |
| 4 | **NightRun** | `Scenes/NightRun.unity` (+ `Scenes/NightRun/` 63 probe EXRs) | The generated city, mission rig, intro rig: ≈15,236 GameObjects, 862 lights, 63 reflection probes, 1 `PlayableDirector` | `MissionSceneEntry` (missions) **and** `IntroSceneEntry` (`IIntroEntryPoint`) |

The NightRun scene hosts **two** entry points. `GameFlow.FindEntryPoint` picks the `IIntroEntryPoint` one only for `GameState.Intro`. The intro rig is inert during missions (shots, overlay and stage lights are off), and `IntroTests.NightRunScene_HasAWiredIntro` checks this.

## `GameRoot`: what it creates (`Scripts/Game/GameRoot.cs`)

`[DefaultExecutionOrder(-1000)]`, `Awake`:

| Object | Purpose |
|---|---|
| `NeonRiftControls` | Generated Input System wrapper (Driving and Menu maps) |
| `RunSession` | Selected car, rivals, mission, last result |
| `AudioMixerService` | Mixer snapshots and user volumes (mixer set to unscaled time so fades work while paused) |
| `GameSettings` | Loads and applies PlayerPrefs settings |
| `GameFlow` | Scene state machine |
| `GameContext` | Bundle handed to every scene: `Config`, `Session`, `Flow`, `Controls`, `Audio`, `Settings` |
| Music toggle `InputAction` | `<Keyboard>/m` and `<Gamepad>/buttonNorth` → `GameSettings.ToggleMusic()`, enabled globally |

`Start` applies the saved audio and graphics settings, then awaits `GameFlow.BootAsync`.

## `LoadingOverlay`

`Scripts/Game/LoadingOverlay.cs`: a full-screen UI Toolkit fade that starts opaque (so the empty Bootstrap scene is never seen). `ShowAsync` and `HideAsync` are awaited by `GameFlow.TransitionAsync`.

## Generated scenes: do not hand-edit
