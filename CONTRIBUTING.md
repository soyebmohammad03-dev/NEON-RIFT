# Contributing

Neon Rift is a personal project with all rights reserved ([LICENSE.md](LICENSE.md)). Issues and suggestions are
welcome; pull requests are reviewed case by case, and contributing does not grant a licence to reuse the project.

## Setup

Follow [Docs/INSTALLATION.md](Docs/INSTALLATION.md): Unity 6000.6.4f1, Git LFS installed **before** cloning or
committing, open the folder in Unity Hub.

## How the project is organised

- First-party content lives in `Assets/_NeonRift/`; one assembly per module under `Scripts/<Module>/`
  ([Docs/Architecture.md](Docs/Architecture.md)). Dependencies point downwards only.
- The two levels and the campaign layer live in `Assets/_NeonRift/Levels/` (`HarborRain/`, `Campaign/`).
- Third-party content lives in `Assets/ThirdParty/<Source>/…`, unmodified, each folder with an `ATTRIBUTION.txt`.
- Most of the world is **generated by editor code** (Night Run district, intro, garage, Harbor Rain, campaign data).
  Change the builder and rebuild with its `Neon Rift ▸ …` menu ([Docs/BUILDING.md](Docs/BUILDING.md)); don't
  hand-edit generated scenes, meshes or prefabs, because the next build overwrites them.
- Conventions: [Docs/Conventions.md](Docs/Conventions.md). Source control and YAML merging:
  [Docs/SourceControl.md](Docs/SourceControl.md).

## Rules that keep the project working

1. **Keep the standalone Night Run bootstrap (`Scenes/Bootstrap.unity`) and its config unchanged.** Campaign
   behaviour goes behind `context.Campaign != null`.
2. **Binary assets go through Git LFS.** `.gitattributes` routes models, textures, audio and archives; check
   `git lfs status` before committing.
3. **Licensing first.** Only add third-party assets with a source URL and a licence that allows redistribution in a
   public repository. Record them in `ATTRIBUTION.txt` and [Docs/ThirdParty.md](Docs/ThirdParty.md). Never commit the
   local-only assets listed in `.gitignore` (Harbor Rain cars, the work boat, voice recordings).
4. **Don't commit** `Library/`, `Temp/`, `Logs/`, `Builds/`, `UserSettings/`, IDE files, APKs or credentials.
5. **Test before you push.** Run the EditMode suite and the playtest or validator closest to your change
   ([Docs/TESTING.md](Docs/TESTING.md)), and say in the pull request which ones you ran and what they reported.
6. Commit messages: a short summary line in the imperative or as a feature title, then details if useful.
